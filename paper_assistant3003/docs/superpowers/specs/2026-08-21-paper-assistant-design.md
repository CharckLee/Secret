# 论文写作辅助与格式标准化工具 — 设计规格

> 版本：v1.0
> 日期：2026-08-21
> 状态：已确认，待实现

## 1. 项目定位与边界

面向本科生/硕士生毕业论文初稿阶段的**轻量化本地 Web 辅助工具**。

**能力边界（需在多处界面静态提示）**：
- 文稿处理全部在浏览器本地，原始内容不上传远端服务器。
- 不接入全网学术论文数据库，不实现知网式查重，不可替代学校官方查重系统。
- 界面统一命名：**文稿语义相似片段自查**（禁止使用"查重"字样）。
- 不做降重/机器改写等灰色功能，不做账号系统，不云端存原稿。

## 2. 关键决策汇总

| 决策点 | 结论 |
|---|---|
| 交付方式 | 整体设计 + 分期实现 |
| AI 润色模型 | DeepSeek API，Next.js 服务端 API route 代理，key 存 `.env.local` 不暴露浏览器 |
| 语义模型 | bge-small-zh-v1.5（`onnx-community/bge-small-zh-v1.5-ONNX`），transformers.js + Web Worker 懒加载，首次联网下载后缓存本地、之后离线可用 |
| 比对粒度 | 句子级计算 + 相邻高相似句子聚合成片段展示 |
| 参考文献输入 | 首批仅纯文本粘贴（知网/万方/百度学术复制条目），自动类型识别 |
| 技术栈 | Next.js 16 + TypeScript + TailwindCSS；mammoth 解析 docx；IndexedDB（Dexie.js）；vitest 单测；端口 3003 |

## 3. 总体架构：纯客户端 + 单一服务端代理

核心原则：**文稿处理全部在浏览器，服务端只保留一个润色代理接口**。

- Next.js 16 App Router 承担：页面骨架、全局导航、`/api/polish` 润色代理。
- docx 解析（mammoth）、格式校验、参考文献标准化、语义向量化全在浏览器本地。
- 语义模型 Web Worker + 单例懒加载：首次点"开始比对"才加载，避免首屏卡顿。

```
app/
  layout.tsx            全局布局 + 导航 + 边界提示条
  page.tsx              首页工作台
  editor/page.tsx       文稿编辑页（含润色侧栏）
  references/page.tsx   参考文献管理
  similarity/page.tsx   语义相似比对
  api/polish/route.ts   DeepSeek 润色代理（唯一联网点）
components/
  Card.tsx              统一圆角卡片基类（封装 hover: scale 1.02 + 阴影 + 200ms）
  ...                   其他 UI 组件
lib/                    纯逻辑（不依赖 React，可单测）
  db/       IndexedDB 封装（Dexie）
  format/   格式校验引擎
  reference/  GB/T 7714 解析与格式化
  similarity/  embedding + n-gram + 片段聚合
  text/     清洗、句子切分、全半角统一
  types.ts  共享类型定义
worker/
  embedding.worker.ts   语义向量化 Worker
```

**关键原则**：`lib/` 全部纯函数/纯逻辑，与 React 解耦，便于单测与独立演进。

## 4. 数据层：IndexedDB（Dexie.js）

| 表 | 字段（要点） |
|---|---|
| `documents` | id / title / content / sourceFormat / createdAt / updatedAt |
| `references` | id / raw（原文）/ type / fields（解析字段）/ formatted（规范化结果） |
| `settings` | 本地偏好（模型已加载标记、比对阈值等） |
| `embeddingCache` | textHash → 向量（Float32Array），避免重复计算 |

API key 不存浏览器，放 `.env.local`；浏览器只把选段文本发到 `/api/polish`。

## 5. 功能模块设计

### 5.1 文档导入与文本解析
- 支持：粘贴纯文本、上传 `.txt`（FileReader 直读）、上传 `.docx`（`mammoth.extractRawText` 读正文保留段落）。
- 在线文本编辑器：实时编辑、删减、分段调整，内容自动持久化到 `documents`。

### 5.2 论文格式智能校验
`lib/format/` 规则引擎，输出**违规项清单**（位置 + 类型 + 修改建议）：

| 校验项 | 规则要点 |
|---|---|
| 标题层级 | 识别一/二/三级标题（如 `一、`/`（一）`/`1.`/`1.1`），校验层级统一性 |
| 段落缩进 | 正文首行缩进 2 字符 |
| 空行 | 检测连续/多余空行 |
| 图表标注 | 图题在下、表题在上 |
| 公式编号 | 公式编号（1）（2）右对齐 |

提供**一键基础排版清理**：统一行距、分段格式（不改变内容语义）。

### 5.3 参考文献批量标准化（核心，GB/T 7714-2015 顺序编码制）
`lib/reference/` 纯逻辑，管线：

```
原始条目 → 格式嗅探 → 类型识别 → 字段抽取 → 格式化 → ParsedReference{type, fields, formatted}
```

- **类型识别**（规则特征，优先级从高到低）：
  | 类型 | 特征 |
  |---|---|
  | 电子文献 [EB/OL] | 含 URL 且无卷期页码，或含 `[EB/OL]` |
  | 学位论文 [D] | 含"学位论文/硕士/博士/[D]/大学" |
  | 期刊论文 [J] | 含卷、期、页码 或 刊名+年（兜底默认） |
  | 专著 [M] | 含出版社+出版地，无卷期 |
- **字段抽取**：作者列表、年份 `(19|20)\d{2}`、卷期 `(\d+)\((\d+)\)`、页码 `(\d+)-(\d+)`、DOI `10.\d{4,}/\S+`、URL 等，正则 + 位置启发式。
- **格式化规则**：
  - 期刊：`作者. 题名[J]. 刊名, 年, 卷(期): 页码.`
  - 专著：`作者. 书名[M]. 版本(可选). 出版地: 出版者, 年: 页码.`
  - 学位论文：`作者. 题名[D]. 保存地: 保存单位, 年.`
  - 电子文献：`作者. 题名[EB/OL]. (发布日期)[引用日期]. URL.`
  - 作者著录：3 人以内全列，超过 3 人列前 3 人 + `等`。
  - 全角/半角标点统一，缺失字段用占位符标出（不静默编造）。
- 支持单条录入、批量粘贴多条；条目卡片展示，单条编辑、批量导出。

### 5.4 AI 学术文本润色（集成进编辑页，不设独立页）
- 编辑页内框选段落 → "润色" → 侧栏**双栏对比**（左原文 / 右润色版）。
- 每个结果带"采纳替换 / 放弃"，采纳即写回编辑区。
- 服务端 `/api/polish` 代理 DeepSeek，提示词约束：优化语句逻辑、剔除口语化，**严格保留科学观点、实验数据、核心结论**。
- 首页"文本润色"入口直接跳编辑页（同一功能，不重复建页）。

### 5.5 语义相似片段自查（核心）
`lib/similarity/` + Web Worker，管线：

```
文本 → 清洗(去空白/全半角统一) → 句子切分(。！？；换行) → 向量化(bge-small-zh)
     → 相似度(语义余弦 + 字面 N-Gram 加权) → 阈值过滤 → 相邻高相似句子聚合片段 → 双栏高亮
```

- **双通道加权**：`score = 0.7×语义余弦 + 0.3×字面 N-Gram(2-gram+3-gram Dice)`，同时命中"复制粘贴"与"同义改写"。
- **性能**：O(N²) 配对，向量余弦在 Worker 批量算；N-Gram 仅对语义粗筛 top-k 候选精算；向量入 `embeddingCache`。
- **两种模式**（同一管线，仅输入组合不同）：
  1. 单文档内部自查：同文档句子两两比，找冗余论述。
  2. 多文档交叉比对：论文句 × 文献库句，找转述来源。
- **展示**：双栏对照（原文片段 | 相似片段 + 相似度分值），阈值滑块可调；语义相似为片段级高亮（非逐词），字面重合逐字符高亮。
- 界面持续提示：仅初稿自查工具，无外部学术数据库，不等同官方查重。

### 5.6 内容导出
- 文稿导出：纯文本 `.txt` / Markdown `.md`。
- 参考文献：单独导出规范化清单（纯文本，可直接粘文末）。
- 任意片段一键复制。

## 6. UI 页面与交互

学术极简浅色、低饱和配色；卡片统一圆角；hover 统一 `scale(1.02) + 阴影加深 + 200ms`（`Card` 基类封装）；每页置能力边界提示条。

| 页面 | 布局 |
|---|---|
| 首页工作台 | 功能导航卡片（5 入口）+ 历史文稿卡片（读 `documents`）+ 边界提示 |
| 文稿编辑页 | 左编辑区（粘贴/.txt/.docx 导入），右实时格式检测面板；含润色侧栏 |
| 参考文献管理 | 条目卡片列表，单条编辑 / 批量粘贴导入 / 批量导出 |
| 语义相似比对 | 模式切换 + 阈值滑块 + 双栏对照 |

**导航映射**（首页 5 个功能入口 → 实际路由）：
- 文稿编辑 / 格式检测 / 文本润色 → 均进入 `editor`（编辑区 + 右侧格式检测面板 + 润色侧栏，同页复用）
- 参考文献管理 → `references`
- 语义相似自查 → `similarity`

## 7. 错误处理与降级

| 场景 | 处理 |
|---|---|
| 语义模型未下载且离线 | 提示，**降级到纯 N-Gram 字面匹配**（功能可用，仅语义通道失效） |
| 润色接口失败/超时/key 缺失 | 报错提示，不影响其他本地功能 |
| docx 解析失败 | 提示"格式不支持或文件损坏"，建议转 txt |
| IndexedDB 不可用（隐私模式） | 降级到内存态 + 警告"关闭页面后数据不保留" |

## 8. 测试策略（vitest）

`lib/` 纯逻辑重点覆盖：
- 参考文献解析：4 类真实样本各若干条，断言字段 + 格式化结果。
- 格式校验规则：标题层级/缩进/空行/图表标注/公式编号。
- 相似度计算：语义+字面加权、片段聚合逻辑。
- 句子切分、文本清理、全半角统一。

## 9. 实现计划（分期）

1. **Phase 1**：Next.js 骨架 + 统一 UI（Card 基类、导航、边界提示条）+ IndexedDB 存储。
2. **Phase 2**：参考文献标准化 + 语义相似自查（核心模块做深，含 Worker、embeddingCache、双栏展示）。
3. **Phase 3**：格式校验 + AI 润色 + 导出。
4. 运行验证命令（`next build`、`vitest`）并收尾。
